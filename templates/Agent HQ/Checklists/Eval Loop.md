# Eval Loop

Use real observed cases to improve behavior, evidence and usefulness. Without recorded memory cutover, follow `Reference/Legacy Workflows/Eval Loop.md` only; its log/facet formats remain historical reference after cutover.

With cutover, preserve old eval logs and save only meaningful findings as managed review records through the applicable successful transaction. Do not append a routine success row to legacy Run Log.

A useful case states the request, required sources, expected/forbidden behavior, source-trace expectations, actual result and uncertainty. Promote repeated failures, high-stakes near-misses or unusually useful behavior; cluster only recurring/material patterns. Test dated beliefs, counterevidence, source independence, commitments versus ideas, completion evidence, confidently wrong answers, missed evidence and unjustified abstention. Assess outcomes rather than exact wording.

Use `glide-integrity` for deterministic provenance/recovery checks, weekly two-uncertain/one-ordinary human samples and eligible overlays. Deliver samples in conversation; internal records are not delivery. Opt-in, frozen regression/held-out cases, weekly candidate limits and rollback govern activation. Model judgments are advisory, never sole acceptance evidence; three samples are not a trust score.

Keep raw private transcripts/connector dumps out of eval files. Add no telemetry, external service or schedule from an eval finding. Broader behavior changes remain proposals for user review.
