# Input and collaboration

Talk to Glide normally. You do not need to open or edit the internal `Now` view, queues, proposals or managed records. Agent HQ is its internal workspace; readable links are available when you want to inspect evidence. The agent brings questions and reviews into conversation, then records your answer.

A shared note is optional. If a decision or draft benefits from a working document, use your ordinary vault notes outside `Agent HQ/`, at the root by default and following your existing unique-note, naming and linking conventions. Agree on the document and sections the agent may change. New collaborative notes identify AI assistance with small frontmatter and a visible disclosure, for example:

```markdown
---
ai_assisted: true
ai_scope: Draft section
---

AI assistance is limited to the Draft section. The owner maintains the responses below it.
```

Your own writing remains yours, including later edits inside an AI draft. The label and location do not grant permission to rewrite it. Do not apply these properties to existing original writing without authorization.

The [canonical checklist](../templates/Agent%20HQ/Checklists/Input%20and%20Collaboration.md) defines the delivery, ownership and receipt boundary. Routine questions remain in conversation; there is no second inbox for you to maintain. Automatic knowledge mode changes ingestion policy, not this boundary.

## Install or upgrade

Install the checklist and merge its short routes into active agent instructions, the memory protocol, review skills and daily/weekly/decision procedures. Inspect local customizations first. Record any selected collaboration destination and edit scope in private instance context; these are agent-readable choices, not new runtime configuration keys. No collaboration folder or example note is created automatically.

Review saved automation prompts as well as their templates: deliver every required question in the configured conversation with enough context to answer there. Update only authorized jobs. Internal queues, proposals, views and receipts stay internal. Create a shared working surface only when needed and authorized; connect it to the internal record while preserving the existing history. Do not bulk-migrate drafts or queue items into ordinary notes.

The runtime, schema, restricted source permissions and proposal → revision validation → apply → receipt contract are unchanged. The memory broker has no general writer for collaborative notes. A shared-file edit needs an available, separately authorized narrow capability; otherwise keep the draft and input in conversation. Do not relax vault-wide protection. A checkbox or edited note is input evidence, not a writer receipt. [Approved project-progress notes](DAILY-NOTES.md) retain their separate category scope and do not authorize collaborative editing.

Preserve previous instruction hashes for rollback without reverting newer owner decisions or authored text. Validate the [synthetic scenarios](../examples/input-surface-cases.json) before treating a routing update as verified behavior, and observe the next real request for input.
